## 最终题目

**《面向事务型键值存储的覆盖引导式模糊测试与崩溃复现平台》**

**待测软件**定为自制的 C++ 命令行程序 **MiniKV**。它从标准输入读取命令脚本，在内存中执行 `BEGIN`、`PUT`、`GET`、`COMMIT` 和 `ROLLBACK`。**测试平台**用 Python 实现，接收待测软件目录，自动生成输入、启动程序、捕获崩溃并输出可重放的缺陷报告。大模型用于辅助设计、编码和调试，平台运行全程可以离线完成。

选择事务型键值存储，是因为它在很小的实现范围内就有三层可测行为。`PUT k 3 abc` 有明确的**命令语法**，声明的 `3` 必须等于实际数据的**字节长度**，提交和回滚则有依赖前序操作的**状态与结果**。尤其是回滚，其正确结果可以直接验证：事务结束后，读取应得到事务开始前的已提交值，原来没有该键时应返回 `NOT_FOUND`。

## 待测软件和平台设计

| 预置教学缺陷 | 触发方式与预期证据 |
|---|---|
| **写入边界导致堆缓冲区越界** | `PUT` 的堆缓冲区有 64 字节，正常最多存 63 字节文本和一个终止符。缺陷版错误接受 64 字节文本，写终止符时越界。平台从短文本种子生成 63、64、65 字节等候选，并同步更新声明长度。 |
| **回滚后读取触发释放后使用** | 正常种子为 `BEGIN → PUT → GET → COMMIT → GET`。把 `COMMIT` 变异为 `ROLLBACK` 后，回滚释放暂存值，但缺陷版漏清理读取缓存，最后一个 `GET` 会访问已经释放的内存。 |
