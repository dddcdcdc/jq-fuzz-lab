# 实验报告

## 结论摘要

- 平台的退出判定以进程异常状态为依据。修正前会把带 `Assertion failed:` 字样的普通错误报成崩溃，修正后不再误报，真实缺陷仍被识别。
- 用 263 条确定性用例逐例核对 jq 1.8.0 与 1.8.1：两次运行各 263/263 通过；两版共享的 257 条用例输出完全一致，0 处差异。
- 平台自检 23 项全部通过，覆盖误报、超时、启动失败、输出截断、中文与空格路径，以及超长种子、未确认崩溃和比较完整性。
- 随机实验扩大到 10 个随机种子、每次 1000 次候选，两种策略共 20000 次执行；20 次运行全部在预算内重新发现同一处历史缺陷，另有 4 次运行发现第二处崩溃签名（无限递归导致的内存耗尽退出，两版一致）。
- 复核发现的三个边界问题已修正：超长种子直接拒绝、未确认崩溃不计入可复现缺陷、版本比较报告缺失用例。
- 该缺陷是上游已公开并已修复的 `src/locfile.c` 断言缺陷，本项目的工作是**自动重新发现**它，不是首次发现。
- 未完成项：Windows 官方二进制没有插桩，覆盖引导与边覆盖统计未实测；确定性用例覆盖的是常用功能子集。

## 一、判定器修正

旧判定器在错误输出中匹配 `Assertion failed:` 或 ASan 文本，只要命中就判为崩溃。这会把普通应用错误当成崩溃。复现：执行 `error("Assertion failed: application message")`，jq 以 5 正常退出，旧版平台仍报 `crash`。

修正后崩溃只由异常状态认定：Windows 侧使用异常码集合（`0xC0000005`、`0xC0000409` 等），POSIX 侧使用信号；断言文本只用于给**已确认的异常**补充签名；ASan 诊断只在目标声明 `address_sanitizer` 时参与判定。同一输入现在返回 `rejected`。

| 输入 | 版本 | 退出状态 | 修正前 | 修正后 |
|---|---|---:|---|---|
| `error("Assertion failed: application message")` | 1.8.0 | 5 | crash（误报） | rejected |
| `error("ERROR: AddressSanitizer: fake report")` | 1.8.0 | 5 | crash（误报） | rejected |
| 缩减样本 `(` + 换行 | 1.8.0 | 3221226505 | crash | crash |
| 缩减样本 `(` + 换行 | 1.8.1 | 3 | rejected | rejected |

回归证据：[旧版重放](demo/replay-1.8.0.json)、[修复版重放](demo/replay-1.8.1.json)。

## 二、确定性用例

用例库 `targets/jq-cases/cases.jsonl` 共 269 条，每条记录 argv、标准输入、预期退出码、预期输出；按版本标记的 12 条每次只执行 6 条，单次运行 263 条。

| 类别 | 数量 | 判据 |
|---|---:|---|
| normal | 85 | 与预期输出逐字节一致 |
| boundary | 34 | 同上，覆盖空值、空容器、中文、转义、数值边界、有界嵌套 |
| error | 26 | 退出码 + 错误文本片段 + 分类（正常拒绝而非崩溃） |
| property | 88 | 预期值由 Python 独立计算：排序顺序、幂等、去重数量、键顺序、分组计数、base64 往返 |
| params | 24 | 输出模式与命令行组合：紧凑/展开/制表符/缩进、`-r`、`-j`、`-s`、`-n`、`--arg`、`-e`、`-S`、`-a`、`--raw-input`、多文件 |
| regression | 12 | 6 组截断脚本在 1.8.0 上断言崩溃、在 1.8.1 上被正常拒绝 |

结果：

| 运行 | 通过 | 失败 | 耗时 |
|---|---:|---:|---:|
| jq 1.8.0 | 263/263 | 0 | 见 `suite/1.8.0/summary.json` |
| jq 1.8.1 | 263/263 | 0 | 见 `suite/1.8.1/summary.json` |
| 两版共享用例对比 | 257 条 | 0 处差异；缺失 0、新增 0、版本专属 12 | — |

比较同时检查用例集合是否完整：缺失、新增与版本专属分别统计，出现缺失或新增时命令返回非零，避免只比较交集。

逐例记录在 [suite/1.8.0/cases.jsonl](suite/1.8.0/cases.jsonl) 和 [suite/1.8.1/cases.jsonl](suite/1.8.1/cases.jsonl)，每条含 argv、输入、预期、实际输出、分类、退出码与耗时。对比结果见 [comparison.json](suite/comparison.json)。

预期不是从二进制回填的。首版生成后有 8 条不通过，逐条核对后确认全部是预期写错（例如 jq 对 `"" | split(",")` 返回 `[]`、保留输入字面量 `-0`、`join` 会遍历对象值），修正记录见 [开发记录](../prompt/development-log.md) 第 11 条。

## 三、平台自检

`python -m unittest discover -s code -p "test_*.py"` 共 23 项，覆盖：

- 判定：普通错误带断言文本仍为拒绝；真实 abort 为崩溃；ASan 只在声明插桩时生效；POSIX 信号。
- 运行器：超时、启动失败、输出截断、中文与空格目录、附加参数、辅助文件、stdin 传递。
- 机制：缩减保持故障签名、固定随机种子下变异序列可复现。
- 输入边界：超过 8192 字节的种子直接拒绝；变异连续 100 次超出上限时报错，不再无限生成。
- 确认边界：最终确认未复现的崩溃标记为 `unstable`，不计入可复现缺陷，摘要单列。
- 对比完整性：版本比较分别报告缺失、新增与版本专属用例，出现缺失或新增时返回非零。

## 六、版本回归与缺陷本身

上游记录显示，某些脚本在文件末尾存在语法错误时，1.8.0 会在错误定位代码中触发断言，1.8.1 修复。本项目用公开案例做环境自检，再从正常种子自动重新触发：

- 公开案例自检：[1.8.0](upstream-1.8.0.json) 断言退出 3221226505；[1.8.1](upstream-1.8.1.json) 语法错误退出 3。
- 自动重新发现：种子 7、结构化变异，第 6 次执行命中，52 字节缩减到 2 字节；[缺陷报告](demo/bug-001/report.json)。
- 版本回归：6 组截断脚本（`(`、`[`、`{`、`if`、`.[`、`1 as`）在 1.8.0 上全部以 `0xC0000409` 退出并打印同一条断言，在 1.8.1 上全部以 3 退出并给出语法错误。

根因位于语法错误定位：截断脚本使定位区间到达文件末尾，旧版检查要求结束位置严格大于起始位置，错误处理过程本身触发断言。 [上游缺陷 #3348](https://github.com/jqlang/jq/issues/3348) · [修复 PR #3350](https://github.com/jqlang/jq/pull/3350)

## 七、第二处崩溃签名：无限递归导致的内存耗尽

结构化变异在 4 次运行中触发了与历史缺陷不同的退出状态。缩减后的输入（69 字节）：

```jq
def normalize: if normalize == "ay" then sort[] end;
[4] | normalize
```

现象：进程先打印 `jq: error: cannot allocate memory`，随后以 `0xC0000409` 结束，耗时约 1.9 秒，**1.8.0 与 1.8.1 表现一致**。

| 项目 | 结果 |
|---|---|
| 触发条件 | 非尾递归函数在判断条件求值前无条件调用自身，栈与堆持续增长直到分配失败 |
| 退出状态 | `0xC0000409`（abort），平台判为崩溃 |
| 版本差异 | 无，两版一致 |
| 分类 | 资源耗尽型退出；jq 的分配器在失败时直接 abort，属于实现选择 |

报告把它单列为“第二处崩溃签名”，**不计入功能缺陷数**：它不是逻辑错误，也不构成版本回归。平台仍然把它识别为崩溃而不是普通错误，依据是进程确实以异常状态退出，而不是错误文本里出现了什么字样——这正是第一节那次修正要达到的效果。 [结构化种子 37 的第二次发现](experiment/structured-37/bug-002/report.json)

同一批运行里还有 3 次超时（每次运行 1 次），均出现在结构化变异，说明部分生成输入会长时间计算而不退出；平台把超时单列，不混入崩溃。

## 八、局限

1. 覆盖引导未实测：Windows 官方二进制没有插桩，`guided` 模式的代码路径只有 Linux 构建入口，未在本机验证。
2. 缺陷数量有限：20 次运行反复命中同一处历史缺陷，另有 4 次命中同一处资源耗尽型签名；同类退出按签名去重，重复触发次数不计为多个缺陷。
3. 用例覆盖是子集：每版 263 条用例覆盖常用功能与错误路径，不等于 jq 的完整语义覆盖。
4. 随机实验的结论限于此构建、语料、变异器和缺陷，不构成“结构化变异普遍更优”的一般结论。
5. 录像为三段连续镜头：录制环境的控制台在输出超过可见行数后停止刷新，分段保证每段完整；命令为脚本按序执行，输出均为真实运行结果。
